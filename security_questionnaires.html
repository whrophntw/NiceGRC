GRC Operations > Security Questionnaires

Security questionnaires are repetitive by design. A customer asks whether data is encrypted, whether access is reviewed, whether backups are tested, whether incidents have a process. The questions change shape; the answers usually do not.

This makes them a good candidate for agent automation. Not because the agent is brilliant, but because the job is mostly retrieval, matching, citation, and careful formatting. In other words: the kind of work machines should be doing before a human gives the final blessing.

The simple version

  • Question comes in. A spreadsheet, portal prompt, email, or audit request asks the same thing in slightly different words.
  • Agent maps it. The agent finds the closest approved answer and the ISO 27001 controls behind it.
  • Agent gathers proof. It pulls the evidence list: policy names, screenshots, exports, cloud settings, or ticket records.
  • Human approves. The answer is reviewed before it goes to a customer. The agent drafts; the human signs.

Example

A customer asks:

Do you encrypt customer data at rest and in transit?

The agent does not need to invent a beautiful essay. It should find the approved encryption answer, map it to the right controls, and return something boring and usable:

Yes. Customer data is encrypted at rest and in transit.
At rest: Azure-managed or customer-managed encryption keys.
In transit: TLS 1.2+.
Controls: ISO 27001:2022 A.8.24, A.8.10.
Evidence: Key Vault inventory, storage TLS configuration, encryption standard.

That is the whole trick. The answer is not magic. It is an approved sentence, attached to controls, attached to evidence.

What the agent needs

  • A library of approved answers — short, reusable responses for common questions.
  • A control map — which ISO 27001, SOC 2, NIST, or internal controls support each answer.
  • An evidence map — where the proof lives: Azure policy, RBAC exports, backup records, incident tickets, access reviews, or screenshots.
  • A draft status — if no approved answer exists, the agent drafts one and marks it for review.

Why this is useful

The value is not that the agent "knows compliance." It does not. The value is that it can stop the same answer from being rewritten twelve different ways by twelve different people. It can keep the wording consistent, attach the correct evidence, and show where the gaps are.

If the control is not assessed, the answer should say that. If the evidence is missing, the answer should say that too. A blank is better than a confident lie in a nice suit.

The practical workflow

  • Build a small answer library from real questionnaires.
  • Tag each answer with controls and evidence.
  • Let the agent match new questions to the library.
  • Let the agent draft unknown answers, but mark them as draft.
  • Have a human approve anything before it leaves the building.

That is a security-questionnaire agent. Not a genius. Not a lawyer. A careful clerk with a filing cabinet, a map, and enough discipline to admit when the drawer is empty.
